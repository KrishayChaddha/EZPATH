Robot Tuning Guide

Everything you need to understand the tuning process for a V5RC robot using LemLib or EZ-Template. Start with physical measurements, calibrate sensors, tune movement, then build your autonomous.

Physical Measurements Odometry IMU Tune drive PID Tune turn PID Slew LemLib EZ-Template

1. Measure the robot before tuning

This is one of the most important parts of tuning. Your code needs to describe the physical robot accurately. If the measurements are wrong, you can spend hours changing PID values when the real problem is your geometry.

Drive wheel diameter Measure the effective diameter of the wheel actually contacting the field. Wheel wear can make the effective diameter different from the advertised size.
Tracking wheel diameter Measure the actual tracking wheel used by your odometry system. Enter the value consistently in your odometry configuration.
Tracking wheel offset Measure the perpendicular distance between the tracking wheel and the robot's center of rotation.
Wheelbase / track width Measure the distance between the left and right sides of the drivetrain according to the geometry required by your framework.
Robot width Measure the physical robot width. This matters when planning paths and determining whether the robot can fit through spaces.
Robot length Measure the robot's front-to-back length.
Do not guess these numbers. If your wheel diameter is wrong, the robot can consistently travel farther or shorter than the distance your software expects.

Measurement rule

Measure the same quantity several times and use a consistent method. Write your measurements down before entering them into code.

2. Set up and test odometry

Odometry estimates the robot's position using encoder/tracking-wheel measurements and heading information. Good PID cannot fix incorrect odometry geometry.

Check these things

1
Wheel diameter
The software needs to know how much distance corresponds to one rotation of the wheel.
2
Tracking wheel position
The framework needs to know where the tracking wheel is relative to the robot's center of rotation.
3
Sensor direction
Positive encoder movement must correspond to the intended direction of movement.
4
Heading
Verify the IMU orientation and make sure the robot's reported heading changes in the expected direction.
Important: Odometry errors usually appear as consistent position errors. Fix the physical configuration first before changing PID.

3. Set up the IMU

The IMU provides heading information used by both autonomous movement and odometry systems.

1
Mount it securely. The sensor should not move around on the robot.
2
Calibrate while the robot is still. Don't move the robot while it calibrates.
3
Test a known turn. Rotate approximately 90°, 180°, and 360° and compare the reported heading with the physical rotation.
If the robot consistently turns too far or not far enough, verify the IMU and framework configuration before aggressively changing turn PID.
EZ-TEMPLATE

4. EZ-Template setup and tuning

EZ-Template provides separate controls for drive PID, heading correction, turning, odometry movement, slew, and other tuning constants. Its documentation also provides a built-in PID tuner.

Basic drive movement

chassis.pid_drive_set(24_in, 110);
chassis.pid_wait();

This gives the robot a distance target and speed limit. EZ-Template documents the speed argument as 0–127.

EZ-TEMPLATE

EZ-Template PID tuning

EZ-Template has separate constants for forward/backward drive, heading correction, and turning. 

void initialize() {

  // Tune drive PID
  chassis.pid_drive_constants_set(
    10,    // P
    0,     // I
    100    // D
  );

  // Heading correction
  chassis.pid_heading_constants_set(
    3,     // P
    0,     // I
    20     // D
  );

  // Tune turn PID
  chassis.pid_turn_constants_set(
    3,     // P
    0,     // I
    20     // D
  );
}

What P, I, and D do

Value Meaning Think of it as
P How strongly the robot reacts to the error "How far am I from the target?"
I How much the error has built up "Have I been off for a while?"
D How quickly the robot is approaching the target "Am I moving toward the target too fast?"
A common tuning approach is to establish useful P response first, add D to control overshoot/oscillation, and only introduce I when persistent error actually requires it.
EZ-TEMPLATE

EZ-Template odometry

EZ-Template supports odometry-based movement and XY point-to-point movement. Its odometry system uses movement and angular PID loops, with separate angular and boomerang constants available. 

void autonomous() {

  chassis.pid_targets_reset();

  chassis.drive_imu_reset();

  chassis.drive_sensor_reset();

  chassis.odom_xyt_set(
    0_in,
    0_in,
    0_deg
  );

  chassis.drive_brake_set(
    MOTOR_BRAKE_HOLD
  );

  chassis.pid_odom_set(
    {{24_in, 24_in}, ez::fwd, 110}
  );

  chassis.pid_wait();
}

EZ-Template coordinates

By default, EZ-Template's odometry coordinate system starts at (0,0) and 0 degrees. Its documentation defines right as positive X, forward as positive Y, and clockwise as positive theta.

Make sure the coordinate system you use in EZPATH matches the coordinate system used by your autonomous code.
EZ-TEMPLATE

EZ-Template slew

Slew limits how quickly the commanded speed increases. It can make acceleration smoother and reduce sudden changes in motor output. EZ-Template allows slew to be enabled globally or for individual movements. 

chassis.slew_drive_set(true);

chassis.slew_drive_constants_set(
  5_in,
  50
);

chassis.pid_drive_set(
  24_in,
  110
);

chassis.pid_wait();
Tune your basic movement first. Do not use slew to hide a badly tuned PID controller.
LEMLIB

5. LemLib setup and tuning

LemLib uses a similar overall tuning philosophy: accurately configure the physical robot, configure sensors and odometry, then tune the movement controllers.

Physical configuration

1
Set up the drivetrain motors.
Verify motor ports, directions, cartridge/gear configuration, and which motors belong to each side.
2
Set up the tracking wheels.
Enter the wheel diameter and the appropriate tracking-wheel position/offset.
3
Set up the IMU.
Make sure the sensor is mounted securely and its orientation matches your code.
4
Create the chassis.
Combine your drivetrain, odometry sensors, and controller settings into the LemLib chassis configuration.

Basic LemLib setup

This is the main setup. Change the motor ports, wheel sizes, offsets, and PID numbers to match your robot.

// Drivetrain
    lemlib::Drivetrain drivetrain(
        &leftMotors,
        &rightMotors,
        11.5,                          // track width
        lemlib::Omniwheel::NEW_275,    // wheel
        450,                            // wheel RPM
        2                               // horizontal drift
    );

    // IMU
    pros::Imu imu(6);

    // Tracking wheel
    pros::Rotation verticalEncoder(5);
    lemlib::TrackingWheel vertical(
        &verticalEncoder,
        lemlib::Omniwheel::NEW_275,
        -2.5                         // offset
    );

    // Odometry sensors
    lemlib::OdomSensors sensors(
        &vertical,    // vertical wheel 1
        nullptr,      // vertical wheel 2
        nullptr,      // horizontal wheel 1
        nullptr,      // horizontal wheel 2
        &imu           // IMU
    );

LemLib PID settings

LemLib uses one controller for forward/backward movement and one for turning.

// Forward / backward
    lemlib::ControllerSettings lateral_controller(
        10,   // kP
        0,    // kI
        3,    // kD
        3,    // anti-windup
        1,    // small error range
        100,  // small error timeout
        3,    // large error range
        500,  // large error timeout
        20    // slew
    );

    // Turning
    lemlib::ControllerSettings angular_controller(
        2,    // kP
        0,    // kI
        10,   // kD
        3,    // anti-windup
        1,    // small error range
        100,  // small error timeout
        3,    // large error range
        500,  // large error timeout
        0     // slew
    );

    // Create chassis
    lemlib::Chassis chassis(
        drivetrain,
        lateral_controller,
        angular_controller,
        sensors
    );

Initialize the robot

Calibrate the sensors when the program starts.

void initialize() {
        chassis.calibrate();
    }
Important: The PID numbers above are example starting values, not universal values. Tune them for your robot.

Simple autonomous movement

These are the basic LemLib commands you will use to move the robot.

void autonomous() {
        // Start at the correct position
        chassis.setPose(0, 0, 0);

        // Drive forward
        chassis.moveToPoint(0, 24, 3000);

        // Turn to 90 degrees
        chassis.turnToHeading(90, 2000);

        // Move to another point
        chassis.moveToPoint(24, 24, 3000);

        // Wait until the movement is finished
        chassis.waitUntilDone();
    }

Set the starting position

Set the robot's starting X, Y, and heading before running your autonomous.

chassis.setPose(
        0,    // X
        0,    // Y
        0     // heading
    );

Go to a point

moveToPoint() moves the robot toward an X/Y coordinate.

chassis.moveToPoint(
        24,    // X
        12,    // Y
        3000   // timeout in ms
    );

Turn to a heading

turnToHeading() turns the robot to a specific field heading.

chassis.turnToHeading(
        90,    // heading
        2000   // timeout in ms
    );

Get the robot's position

You can read the current X, Y, and heading from the chassis pose.

lemlib::Pose pose = chassis.getPose();

double x = pose.x;
double y = pose.y;
double heading = pose.theta;
Easy way to think about LemLib: set up the robot → calibrate → set the starting pose → move to points → turn → test → tune.
LEMLIB

LemLib PID tuning

The important idea is the same as EZ-Template: PID constants control how aggressively the robot reacts to error, how accumulated error is handled, and how motion is damped.

Tune one thing at a time

1
Tune straight driving first.
Test a simple straight drive.
2
Tune turning.
Test simple turns like 90° and 180°.
3
Tune heading correction.
Make sure the robot can stay straight.
4
Tune point-to-point movement.
Do this after basic movement works well.
If your robot drives straight correctly but turns poorly, do not immediately change the drive PID. The turn controller and heading/sensor configuration should be investigated separately.

Basic LemLib movement test

void autonomous() {
        chassis.setPose(0, 0, 0);

        // Test straight driving first
        chassis.moveToPoint(0, 24, 3000);
        chassis.waitUntilDone();

        // Then test a turn
        chassis.turnToHeading(90, 2000);
        chassis.waitUntilDone();
    }
Tuning order: get straight driving working → tune turning → check heading → tune point-to-point movement.
LEMLIB

LemLib odometry

The most important part of LemLib odometry is accurate physical geometry. Your software needs to know how far the tracking wheels move and where those wheels are located relative to the robot.

Odometry test

1
Put the robot at a known starting point.
2
Reset the robot's position in code.
3
Drive a distance you already know.
4
Compare the position shown by the code to the real position.
5
Try the test in another direction.
If the error grows as the robot travels farther, investigate your wheel diameter/calibration. If the robot's position becomes wrong mainly during turns, investigate tracking-wheel offsets and heading information.

LemLib vs EZ-Template

Both frameworks can accomplish the same overall tuning workflow. The API and names are different, so don't copy constants directly from one framework into the other.

Concept EZ-Template LemLib
Drive control Tune drive PID Drive controller
Turning Tune turn PID Turn controller
Heading correction Heading PID Heading control
Odometry EZ odometry LemLib odometry
Path movement Odom / Boomerang / PP Chassis movement functions
Acceleration limiting Slew Movement/controller configuration
Important: PID values are framework- and robot-dependent. A Kp value that works on one robot should not automatically be copied to another robot.

6. Testing order

Use this order. It prevents you from trying to solve an odometry problem with PID or a mechanical problem with software.

1
Check the robot
Wheels, axles, drivetrain alignment, tracking wheels and sensor mounting.
2
Measure the robot
Measure wheel diameters, offsets, robot size, and drivetrain setup.
3
Check sensors
Make sure encoders and the IMU move in the correct direction.
4
Check odometry
Make sure the reported position matches where the robot actually is.
5
Tune drive PID
Tune straight driving.
6
Tune turn PID
Tune turns.
7
Tune point-to-point
Tune movement between field points.
8
Build the autonomous
Once everything else works, tune the full autonomous.

7. Troubleshooting

Problem Check first
Robot travels too far Wheel diameter / distance calibration
Robot travels too short Wheel diameter / distance calibration
Robot drives in an arc Drivetrain alignment, motor configuration, heading correction
Robot overshoots PID response and damping
Robot oscillates PID response / excessive gain
Robot stops short PID gains, exit conditions, friction, mechanical resistance
90° turn is inaccurate IMU, drivetrain geometry, turn controller
Position gets worse after turns Tracking-wheel offsets and heading calibration
Autonomous changes between runs Mechanical consistency, battery, wheel slip, sensor mounting

8. Final tuning checklist

Drive wheel diameter measured.
Tracking wheel diameter measured.
Tracking wheel offsets measured.
Motor ports and directions are correct.
IMU is secure and calibrated.
Robot can drive a known distance accurately.
Robot can turn to known angles accurately.
Odometry matches the real robot.
Tune drive PID has been tuned independently from turn PID.
Tune point-to-point has been tested.
Autonomous tested multiple times.
Final PID/settings were saved and backed up.
EZPATH principle: Measure → Configure → Calibrate → Tune → Test → Repeat. Don't randomly change constants until the robot "looks better."
